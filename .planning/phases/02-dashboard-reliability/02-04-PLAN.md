<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    Dashboard reliability improvements:
    - Intermediate UI states (Starting.../Stopping...)
    - Task list file watching with debouncing
    - Manual task refresh button
    - Project switch state reset
  </what-built>
  <how-to-verify>
    **DASH-01: Start Reliability (2 second requirement)**
    1. With loop stopped, click "Start Build" (or any mode)
    2. Observe button shows "Starting..." with spinner
    3. Within 2 seconds, button should change to "Stop Loop"
    4. Log should show "Session created: [id]"
    PASS: Start shows intermediate state and confirms within 2s

    **DASH-02: Stop Reliability (5 second requirement)**
    1. With loop running, click "Stop Loop"
    2. Observe button shows "Stopping..." with spinner
    3. Within 5 seconds, button should change back to "Start [mode]"
    4. Log should show "Loop stopped via [sigterm/sigkill]"
    PASS: Stop shows intermediate state and confirms within 5s

    **DASH-03: Task List Updates**
    1. Open IMPLEMENTATION_PLAN.md (or prd.json in simple mode) in an editor
    2. Add a new task: `- [ ] Test task from editor`
    3. Save the file
    4. Within 1 second, TaskList should show the new task
    5. Click the refresh button (if update didn't happen)
    6. Verify task appears after manual refresh
    PASS: Task list updates automatically or via refresh button

    **DASH-04: Project Switching**
    (Requires two projects running on different ports)
    1. Note current project's name, task count, and git branch
    2. Switch to a different project (different port)
    3. Verify: Project name changed
    4. Verify: Task list shows different tasks (or empty if none)
    5. Verify: Git branch shows correct branch for new project
    6. Verify: No stale toasts appeared (no false "Loop stopped")
    7. Switch back, verify original project's state restored
    PASS: Project switch loads correct context, no stale data

    **Edge Cases**
    - Double-click Start during "Starting..." - should have no effect
    - Double-click Stop during "Stopping..." - should have no effect
    - Rapid file saves (5x in 1 second) - should not cause 5 updates
  </how-to-verify>

  </resume-signal>
